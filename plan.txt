NixOS Control Panel — Project Implementation Plan

GOAL
Build a self-hosted, Rust-based web interface for managing NixOS systems. Combine Nixdatifier-inspired generation history, flake updates, package diffs, health monitoring, and store management with declarative configuration editing, service management, and package installation.

PRINCIPLES
[x] Keep Nix files as the source of truth
[ ] Support flake-based and traditional NixOS configurations
[x] Never replace or silently rewrite user-managed files
[ ] Separate declared, evaluated, built, and active system state
[ ] Make all configuration changes reviewable and reversible
[x] Design core APIs for eventual multi-host support
[x] Prefer existing Nix commands and module evaluation over reimplementing Nix
[ ] Use open-source dependencies and track their licenses

PHASE 1 — PROJECT FOUNDATION
[x] Create Cargo workspace with core, server, privileged, and CLI crates
[x] Create frontend application
[x] Create Nix flake for development, builds, and packaging
[x] Add NixOS module exposing services.nixos-control.enable
[ ] Add configurable listen address, port, state directory, and authentication
[x] Run server as an unprivileged systemd service
[ ] Set up CI for formatting, clippy, tests, and builds
[ ] Add architecture documentation and contributor guide

PHASE 2 — NIXOS DISCOVERY AND EVALUATION

[x] Extract option types, descriptions, defaults, examples, and declaration locations
[ ] Inspect module import graph and participating modules
[ ] Track declared versus effective option definitions

[x] Provide internal typed APIs for configuration queries
